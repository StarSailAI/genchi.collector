## 原文和重复合并

`genchi.aggregator` 单独标记 editorial / community / official_operator 来源角色。使用经过规范的详情 URL 生成稳定 ID，保留原生 query ID，仅清除已知统计参数和 fragment。正文中的有效链接以原文证据保存，移除推荐卡片、分享和广告等内容。

每次扫描的未处理文章保存在 checkpoint 中。成功文章进入原文/版本库，404/410 退出后续跟踪但不删除历史。部分页面失败时报告 `partial` 并保留失败 URL 等待补采；无法保存任何文章时交给任务退避重试。未完成的积压数量明确记录，不把上限截断说成全站覆盖。

产品层保持人工审核：模型候选不修改已发布活动。发布时，稳定来源映射优先；跨站通过相同官方活动链接、兼容活动类型及举办日期范围匹配，存在多个目标时不猜测。聚合来源不走旧的“同标题、同年份”合并捷径。同篇明确列出的同名场次使用共同活动标识。不同来源的相同节点复用已有节点并追加证据；票价、条件或时间不同的票务不因名称相似而合并。原名参与身份判断，中文展示译名不参与。

票务轮次仅忽略语法性的「チケット／受付」，不丢弃轮次、会员、VIP、价格和条件。没有活动官网时，正文唯一的具体票务链接可作为活动引用。

当前规则仍有边界：官方链接不同、同一巡演的不同日期、日期精度不同或活动改名，可能仍需人工指定已有活动标识。不能把暂时没有匹配到其他来源的候选直接统计为独家活动。

## 抽取与完整性

模型选择原文段落编号，由程序回填精确原文；无法定位的证据和不在原文中的 URL 不通过校验。Anime Hack / Eventernote 的专用日期、开演、开场栏由确定性规则读取；未知开演不会用开场代替，预计终演不作为精确结束。明确逐场列出的日期不允许退化成 TBD。多场次候选使用不同来源键，避免互相覆盖；同版本重处理会关闭被替代的未审核候选，保留历史和人工决定。

animate cafe 的图片尚未 OCR。审核原因、原始图片链接和 `image_details_pending` 提示这一缺口；菜单、特典和图片中的预约规则仍需核对，不能宣称文本提取已经完整。

受付区间若已同时明确开始和截止时刻，模型不能将对应日期窗口降为 DATE。程序校验匹配的原文日期区间后要求重新提取，不借用开演时刻或其他轮次日期，也不拼凑未知的半段时间。SPICE / LiveFans 两组真实候选已通过重提取与合并回归验证。

## 任务幂等与验收记录

本轮发现旧 Controller 只在运行队列里检查任务去重键，任务归档后重复提交会再执行，但新报告因历史表唯一键而被丢弃。已修复为跨运行队列与历史表的持久幂等，并以事务锁防止注册/归档竞态。主动补采必须使用新的任务键。

验收中的 animate 重复任务 `19562` 受到旧问题影响：worker 日志证明完成，7 篇新增原文仍在，但没有独立终态报告。不补造该报告，也不据此推算精确请求成功率。其他验收任务保留原有终态及失败历史。

## 分析口径

在 product 容器内通过标准输入执行 `deploy/analyze-source-value.py --since <带时区的观测起点>`。只读分析当前原文版本对应的处理状态、候选和已发布证据，排除旧版本候选。

- 记录数、活动候选数、已发布活动数分开统计。
- 分别统计活动类型、节点类型、缺失活动日期、官方活动链接和发布日期精度。
- 先用相同官方链接与日期构建对照组，再人工核实它们是否确为同一活动/场次；同一活动的两篇文章可能报道不同更新。
- 用同一活动的票务、抽选、入金、商品、入场方式等节点对比票务平台与聚合站。文章更长或记录更多不意味着更全面。
- 发布时间、上游更新时间、首次观测时间与活动日期必须分开。仅有更新日时不虚构首次发布日期，DATE 不作为精确延迟时刻。
- 对明确相同节点，比较各站首次可见证据；日采集频率和首轮历史补录会影响观测延迟，不能据此直接断言官推慢或快。
- 仅在样本范围、时间窗口、解析成功率和重复匹配都核实后关闭低增量来源。短期失败先记访问问题，解析失败先修解析器。

长期筛选还需要连续日采集观测。同一阶段保留原文与证据；关闭调度不删除既有历史。

## 工作区与部署隔离

共享工作目录存在同时进行的认证/订阅重构。本次采集开发已迁至独立 Git worktree，后续只部署明确列出的采集文件，不使用“全部未跟踪文件”作为发布范围。

首次部署前已完成数据库备份。部署时误包含另一工作流新增的 `0008_email_code_auth` 迁移；核对备份及当时的当前库，账户、会话和登录令牌均为空，没有现有用户受到影响。已执行迁移须保留，不能删除迁移文件或将数据库版本号强制调回旧值。数据库为 SchemaContract 1.5，后续产品镜像必须兼容；本次来源调度和 worker 更新不需要新增数据库迁移。
