## 本次修复

- 官网使用各自的标题、正文和发布日期选择器，移除导航与相关文章污染；补齐分页。偶像大师等待真实新闻列表加载，避免把导航栏链接误当成页面准备完成。
- 只公布日期时保存 DATE 精度。e+ 可从对应公演区块补充明确的开演时刻；ぴあ和 Lawson 不再伪造午夜开演。
- e+、ぴあ的已失效详情按 404/410 记录、退出跟踪，保留历史，并继续采集。Love Live! 的特定“页面不存在”403 提示单独识别；普通权限拒绝仍失败。
- 票务发现与历史复查分别保留名额，详情游标轮转，防止列表尾部长期无法采集。每天覆盖全部配置的地域/关键词；详情数量仍有单轮上限。
- Lawson 显式识别官网的“无符合条件票务”页面，并在任务报告记录空结果关键词；空白页面或加载失败仍报错。
- Lawson 以 L-code、受付类型和原生 schedule 编号识别受付，避免同名、同时开售的不同票种互相覆盖截止时间。多日券与首日指定票分开保存。旧受付映射使用 `deploy/repair-lawson-rounds.py` 预览后修复，保留现有节点 ID、旧映射和历史；若已有轮次参与记录则停止并要求另行核对。
- 浏览器对单页临时错误有限重试；短期限流先按 Retry-After 等待至少 60 秒后重试本页，长时间或持续限流交由调度器退避。Firefox 子进程退出后可自动恢复，正文采集不下载无用媒体。请求指定的选择器缺失时不再假装成功。
- 生产运行配置独立挂载到 `/app/runtime/sources.yaml`，避免部署代码时覆盖嵌套挂载，导致来源开关失效。
- DeepSeek 使用官方非思考模式，避免输出预算耗在推理而没有 JSON；格式或引文校验失败时只给一次纠正机会，纠正后仍使用同一套校验。仅空白差异的引文须唯一定位回原文，存储原文中的真实连续片段；不接受改字、改日期或拼接不同段落。失败保留审核，模型候选不会自动发布。
- ASOBI 活动入口和通票元记录只索引，不伪造额外演出。成功重新处理同版本后关闭对应的系统失败记录，保留正常候选的人工审核。

本轮数据库核对覆盖 361 条实际观测记录：334 条后续处理完成，27 条保留审核，没有待运行或重试中的解析任务。已发布场次、节点时间与当前原文版本的对应关系未发现不一致。上述数量与手动任务的详情页统计口径不同；例如ぴあ两轮共观测 53 个不同原始资源。

27 条待审核分别为 ASOBI 的 13 条缺少明确场次关联的受付，以及 14 条官网新闻的引文或时间结构未通过校验。正常提取、等待编辑确认的活动候选另行保留，不计入这 27 条失败审核。

## Lawson 旧受付映射修复

新采集版本以原生受付编号区分票种。已有部署先备份并暂停 normalizer，完成新版本 Lawson 手动采集后，在 product 容器中执行以下脚本，`--observed-since` 填该任务的实际开始时间：

```bash
sudo docker exec -i genchi-collector-product-1 python - --observed-since '<UTC task start>' < genchi.collector/deploy/repair-lawson-rounds.py
sudo docker exec -i genchi-collector-product-1 python - --observed-since '<UTC task start>' --apply < genchi.collector/deploy/repair-lawson-rounds.py
```

命令在服务器的两仓库上一级执行。先检查预览，再应用，最后恢复 normalizer 处理新版本。本次实际修复 3 个已发布受付的映射，没有删除任何历史场次关联；修复后再次预览，待修改项为 0。脚本不发布候选、不删除原文和历史；同一旧 ID 对应多个票种时，必须能从现存时间和条件唯一定位原节点，否则终止。内部受付编号调整不单独增加事实 revision，也不因此发出活动更新提醒。新安装没有旧映射，无需执行。

## 覆盖边界

ASOBI 当前 13 个受付的公开响应没有真实场次关联，其中包含正在接受申请的受付。更详细的场次接口要求认证。原始受付时间和内容已保存，这些记录继续待审核，不猜测对应哪一天或哪场演出。

Lawson 搜索页只公开日期时，按日期保存；多日有效券保留起止范围与入场条件，不把两个端点当成两场演出。上游内部时段标识可保留，但没有明确时刻就不能声称已掌握每个入场时段。

一次日采集是有边界的增量扫描：官网两到三页；e+ 最多 80 个详情；ぴあ最多 48 个详情、每详情最多 8 个售票页；Lawson 最多 200 个结果。历史资源保留，不能把总库存数当作当天成功获取数。
